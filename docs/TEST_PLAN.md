# 测试计划

## 自动化测试

运行 `npm run build`、`npm test` 和 `npm audit --omit=dev`。构建必须无 TypeScript 错误；测试必须全部通过；生产依赖审计必须没有已知漏洞。

## 功能与恢复测试

1. 使用本机脚本创建管理员，再公开注册两个普通用户；确认普通注册无法获得管理员权限。
2. 用大小写变体、全角 NFKC 等价名称和并发请求重复注册，确认数据库唯一约束稳定返回 409。
3. 两个用户分别上传同名文件，确认双方列表和内容互不可见；同一用户重复上传同名文件时显示 v1、v2 且旧版本不被覆盖。
4. 上传空文件、1 字节文件、恰好 1 MiB 文件和超过 1 MiB 文件，下载后使用 `Get-FileHash -Algorithm SHA256` 比对。
5. 上传/下载大文件时断网再恢复，确认按缺失分块或已写入偏移恢复，且最终哈希一致。
6. 同时选择多个文件，确认客户端最多三个并行任务，服务端拒绝超过用户活动上传会话上限的预留。
7. 管理员修改用户带宽、配额和状态；确认超配额上传在建立临时文件前被拒绝，禁用后旧访问令牌立即失效。

## 安全测试

1. 连续提交错误密码，确认 IP、用户名/IP 与账户级退避锁定生效，且响应不区分用户是否存在。
2. 将文件名改为 `..\\..\\test.txt` 或包含控制字符，确认服务器拒绝。
3. 修改分块载荷但保留旧哈希，确认服务器返回错误且不记录分块完成。
4. 修改 `offset`、`size` 或 `index`，确认服务器拒绝越界或不一致的分块。
5. 使用用户 A 的令牌请求用户 B 的文件 ID，确认服务器不返回文件。
6. 重复使用同一个 WSS 票据，确认第二次连接以 4401 关闭。
7. 从非 `PUBLIC_ORIGIN` 来源发送请求，确认返回 403。
8. 发送大于允许载荷的 WebSocket 帧，确认连接被协议层拒绝。
9. 启用 mTLS 后，不带客户端证书访问，确认 TLS 握手失败；导入有效 `client.p12` 后再次验证。
10. 检查日志和数据库，确认不存在密码、访问令牌、刷新令牌或 WSS 票据明文。
11. 轮换刷新令牌后重放旧令牌，确认同一令牌族的新令牌也被撤销。
12. 修改密码或执行“撤销所有设备会话”，确认旧访问令牌和刷新令牌都不能继续使用。
13. 尝试 UPDATE/DELETE `audit_log`，确认数据库触发器拒绝操作；检查 `schema_migrations` 当前版本。

## 稳定性测试

建议使用 10 个并发用户，每个用户持续上传和下载随机文件 30 分钟。监控进程内存、CPU、磁盘剩余空间、SQLite 锁等待和失败率。测试结束后随机抽取所有文件重新计算 SHA-256；任何哈希不一致均视为失败。
